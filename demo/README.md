# 澄和医疗 · 客户演示系统

使用 React + Ant Design 蓝白医疗界面，数据保存在本机 SQLite。无需 Docker、Redis、MySQL 或 PHP，仓库已附带数据库和虚构演示数据；数据库不存在时，启动会自动创建，无需登录。

## 环境要求

- Node.js 22.13 或更高版本，建议使用 Node.js 24。
- npm 随 Node.js 安装。首次安装依赖需要联网。

## 开发启动

以下命令在**仓库根目录 `his-app/`** 执行；如果终端当前在 `his-app/demo/`，先执行 `cd ..`。

```bash
npm ci
npm run dev
```

浏览器打开：<http://localhost:3100>

开发模式下，修改前端代码会自动更新页面；修改后端代码后需要重新启动服务。停止服务按 `Ctrl+C`。

## 给客户演示时启动

同样在仓库根目录执行：

```bash
npm ci
npm run build
npm start
```

如果已经安装过依赖且依赖未变，可以跳过 `npm ci`。构建后由本地服务同时提供页面和数据接口，无需另开前端或数据库服务。

打开：<http://localhost:3100/#dashboard>

修改界面代码后，需要重新执行 `npm run build`；修改后端代码后，需要停止并重新执行 `npm start`。重启服务不会清空已有演示数据。

不要同时运行开发版和演示版占用同一个端口。提示端口被占用时，先停止已有服务，或指定另一个端口：

```bash
# macOS / Linux
PORT=3101 npm start
```

```powershell
# Windows PowerShell
$env:PORT = "3101"
npm start
```

使用其他端口时，将浏览器地址相应改为 <http://localhost:3101>。服务默认仅供当前电脑访问。

## 数据保存与重置

- 数据库位置：`demo/data/his.sqlite`，仓库已附带当前演示数据，缺失时自动生成。
- 数据持久保存在本机，刷新页面、关闭浏览器或重启服务不会丢失。
- 演示数据库已提交到 Git，其他电脑拉取仓库后可直接使用这份数据。WAL、SHM 等运行时文件不提交。
- 备份或再次提交数据库前，先停止服务，确保数据已写入 `his.sqlite`。备份可复制整个 `demo/data/` 目录。
- 如需恢复初始数据：点击侧栏「演示设置」→「重置演示数据」，确认后清除当前演示操作，按当天日期重新生成示例。

## 建议演示顺序

1. **工作台**：查看预约趋势、科室分布、床位使用情况和工作提醒。
2. **面诊预约**：新增预约，登记到院、开始接诊，并填写病历。
3. **电子病历**：切换顾客，查看记录，保存草稿或归档。
4. **手术与耗材**：打开进行中的手术，登记耗材。
5. **库存管理**：查看耗材库存扣减及出库流水，也可以演示采购入库。
6. **财务核对**：查看自动同步的项目和耗材费用，完成手术后核对账单并登记收款。
7. **病房床位**：安排入住、办理出院，查看生成的床位费用，再确认清洁完成。

侧栏「演示指南」中也有操作提示。当前版本使用统一管理员身份和虚构顾客数据；收款只登记状态，不会实际扣款。

## 代码位置

| 路径 | 内容 |
| --- | --- |
| `client/src/pages.jsx` | 八个主要业务页面 |
| `client/src/workflows.jsx` | 表单及顾客、手术、账单详情 |
| `client/src/visuals.jsx` | 数据图表和业务看板 |
| `client/src/presentation.css` | 蓝白医疗演示主题 |
| `server.mjs` | 本地页面和接口服务 |
| `store.mjs` | SQLite、演示数据和业务规则 |
| `tests/workflows.test.mjs` | 业务流程测试 |

根目录的 `package.json` 管理启动命令和依赖。原 Laravel 代码仅作参考，不参与演示版运行。
